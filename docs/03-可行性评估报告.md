# 反诈训练 APP 设计方案可行性评估报告

> 评估视角：LLM Agent 系统设计 × 反诈产品与公安反诈流程 × 法律合规 × Uniapp/Trae 平台工程
> 评估对象：「欺诈 Agent — 评估 Agent — 自救 Agent」三 Agent 联动反诈训练 APP 设计方案
> 报告日期：2026-10-20

## 一、总体可行性判断

**一句话结论**：技术可行、产品成立、数据够用、商业偏弱——唯一真正的拦路虎是「生成式诈骗话术」的法律伦理边界；只要把欺诈 Agent 从"自由生成话术"改为"基于官方公开案例的剧本化重演 + 受控生成"，本方案即可放行。

**综合评级**：有条件可行（B 级，合规整改后可达 B+）

| 维度 | 评级 | 一句话理由 |
| --- | --- | --- |
| 技术可行性 | **高（B+）** | 剧本化生成、规则+LLM 混合评估、封闭法条检索均为成熟方案 |
| 产品可行性 | **中（B-）** | 闭环成立，但"愿意被骗"与留存是真实挑战 |
| 法律伦理可行性 | **中低（C+，必须整改）** | 话术滥用风险与《反电诈法》红线需先解决 |
| 数据可行性 | **高（B）** | 公开案例充足合法，法条库小而封闭 |
| 商业可行性 | **低-中（C+）** | C 端付费弱，B/G 端（学校/社区/银行）是主战场 |

## 二、五维度可行性评估

### 2.1 技术可行性 —— 高（B+）

**① 欺诈 Agent 能否稳定生成可信骗术？——能，但要"戴着镣铐生成"。**
完全自由生成有三个问题：不稳定（跑偏剧本）、露馅（前后编造细节矛盾）、越界（生成可直接复用的完整诈骗脚本）。推荐三层架构：

```
检索层（RAG）：官方公开案例库 → 场景剧本骨架（阶段-目标-约束）
生成层：LLM 只做话术润色与追问应答，温度调低（≤0.5），槽位填充（姓名/金额/案情随机化）
护栏层：输出前正则校验——不得包含真实链接/收款账号/电话格式；固定话术打"模拟训练"水印
```

关键工程点：**"虚构事实清单"（ facts ledger ）**——Agent 编造的每个细节（病床号、警号、订单号）必须登记，后续轮次引用时保持一致，否则会被用户一追问就露馅。这是"追问适配"能力的技术核心。

**② 评估 Agent 能否仅凭对话记录判断弱点？——半可靠，必须混合架构。**
纯 LLM 打分有三个硬伤：分数抖动（同对话两次评估差 15 分）、不可解释（说不出为什么）、无法稳定入库。正确做法：

- 8 项指标全部改为**可计算的规则特征**：每条用户消息触发 N 个布尔特征（含"安全账户/转账/验证码"等关键词表、决策用时、对"恐吓话术"的情绪词响应），加权计分；
- LLM 只负责把规则结果**翻译成自然语言分析**（"你在第 3 轮被'逮捕令'话术施压后 10 秒内查看转账卡片…"）；
- 输出固定 JSON Schema（risk_level / reasons[] / advice），便于错题本入库。

**指标体系评价**：您列的 8 项指标方向正确，建议增补 2 项：**是否主动通过官方渠道核实（110/96110/官方APP）**——这是反诈能力的黄金指标；**是否识别二次诈骗话术（黑客追款/维权交费）**——受骗后最致命的一环。

**③ 自救 Agent 能否准确匹配法条？——能，这是三个 Agent 里最容易做准的。**
法条是封闭集合（相关条文约 100–300 条），向量检索 + 关键词双路召回 + 人工校对可达 95%+ 准确率。真正的成本在**维护**（《反电诈法》配套司法解释仍在更新），建立"每季度法律修订 review"机制即可。防幻觉要求：**引用必须带条文原文**，检索不到就不引用，禁止 LLM 凭记忆写条文。

**④ 三 Agent 数据互通、全程记忆在 Trae + Uniapp 下是否可实现？——可以。**
- 单场训练全程记忆：千问/Kimi 128K 级上下文足够；超限时用"结构化摘要 + 用户行为画像"压缩，不必保留逐字对话（这同时满足数据最小化）；
- 跨 Agent 互通：演示版用本地存储即可（训练记录 → 评估报告 → 错题本 → 自救分级）；接后端用任意轻量方案（云开发/Supabase）；
- 本项目已实现该链路：训练页写入 `last_training` → 报告页读取动态评分 → 错题本按场景归档 → 自救页按风险等级出方案。

**⑤ 性能/延迟/上下文限制：**
- LLM 流式输出首包 1–4 秒，用"对方正在输入…"过渡即可接受；
- Uniapp H5 端要控制大阴影/长动画（本项目已做优化：阴影半径 28rpx→14rpx、去除滚动动画）；
- Trae 生成代码质量需人工 review，尤其是合规文案与边界逻辑。

### 2.2 产品可行性 —— 中（B-）

**用户是否愿意被"骗"？——核心矛盾，需要设计化解。**
真实骗子话术越真，用户越不适；太假则无训练价值。四个对策：
1. **知情同意前置**：开训弹窗"您将进入模拟诈骗演练，角色均为虚构"；
2. **难度分级**：L1 剧本演示（旁观找破绽）→ L5 全真模拟，新手不会被劝退；
3. **识破即时正反馈**：每次正确抉择给积分/称号，把"被骗"变成"闯关失败"而非羞辱；
4. **失败即复盘**：一旦中招，立即切"教练视角"逐句拆解，把挫败感转化为学习收益。

**体验劝退点**：等待延迟（用流式+打字机效果）、重复感（剧本槽位随机化：金额/称谓/案情每次不同）。

**闭环是否成立？——成立，但"自救"要降频。**
训练→实时评估→错题本→分级自救在数据上完全可闭环（本项目即是证明）。注意：自救环节对未被骗用户是低频功能，应做成"知识库+演练清单"，不要常驻主流程占位。

**留存预测（假设 A3 场景）**：7 日完课率可达 40–60%（session 短、单次训练 3–5 分钟）；30 日留存难超 15%——除非加入打卡排行/校园积分/班级对战等社交机制。参考教育安全类工具的普遍留存水平。

### 2.3 法律与伦理可行性 —— 中低（C+，必须整改）

**这是全方案唯一可能"一票否决"的维度。**

| 风险 | 法规依据 | 整改要求 |
| --- | --- | --- |
| 生成话术被复制滥用 | 《刑法》第 287 条之一（非法利用信息网络罪）、第 287 条之二（帮信罪）、《反电信网络诈骗法》 | 话术仅存在于产品运行时：禁用长按复制/导出/分享完整对话；截图界面强制带"模拟训练"水印 |
| 生成"可直接使用的"诈骗要素 | 《反电诈法》第 2 章 | 不得输出真实格式的收款账号、涉诈链接、可拨打电话；案例人名/机构/案件全部虚构化改编 |
| 用户对话数据留存 | 《个人信息保护法》：最小必要、可删除 | 演示版本地存储；接入云端时提供"一键删除全部数据"；对话仅保留结构化摘要+关键行为，不存逐字全文 |
| 法律建议越界 | — | 免责声明已列，需补充"不构成法律意见，以办案机关意见为准"；自救 Agent 不得代写报案材料以外的法律文书 |
| 用户挫败感 | — | 评估话术用"薄弱项+提升建议"，禁用负面评价词；建议默认难度 L2 |
| 未成年人 | 《未成年人保护法》 | 若面向中学场景，需教师模式 + 家长知情 |

**关键判断**：方案中的三条安全边界（仅训练用、不用真实信息、明示模拟）方向正确但不够——需补上**"不可导出"与"不可直接复用"**两条技术硬约束，才构成完整防线。

### 2.4 数据可行性 —— 高（B）

- **案例来源充足且合法**：公安部历年公布的十大高发电诈类型及作案手法、国家反诈中心官方通报、人民公安报案例库、裁判文书网公开判决——覆盖 90% 以上常见骗局。要求：改编时对人名/地名/金额/卡号做脱敏虚构，注明"改编自公开通报案例"。
- **法条库构建成本低**：约 100–300 条相关条文，1–2 周可建库；维护依赖季度修订 review；字段设计（编号/适用场景/处罚力度/报案流程/资金冻结流程）合理，建议增加"时效性"字段。
- **错题本驱动训练：可行且是本方案最大亮点**。错题的"诈骗类型"字段直接映射推荐训练场景，形成"薄弱→定向加练→再评估"闭环。数据结构建议完整，只需增加"出现次数"字段以支撑间隔重复（艾宾浩斯复习提醒）。

### 2.5 商业可行性 —— 低-中（C+）

- **C 端付费点弱**：反诈是"低频刚需"，个人订阅意愿有限。
- **可行的商业模式（按现实性排序）**：
  1. **B/G 端宣教采购**：学校安全教育课、社区普法、单位培训——政府采购或校方采购，课程演示阶段即可对接试点（与假设 A3 匹配）；
  2. **银行合作**：作为手机银行内嵌的"防诈课堂"模块，按场景定制（针对该行客群高发骗局）；
  3. **保险增值服务**：家财险/账户安全险附赠反诈训练权益。
- **获客**：96110/派出所联动宣传、开学季进校、"被骗者教育"场景（银行劝阻后推荐）。

## 三、三个 Agent 分别的可行性分析与改进建议

### 3.1 欺诈 Agent —— 剧本化：高 / 自由生成：中

**可行性**：检索+剧本+受控生成的路线完全可行（本项目 utils/data.js 已按公安部通报改编 7 个场景的完整话术脚本，含每轮"骗子应答 + 实时评估 + 判定理由"）。

**改进建议**：
1. 接 LLM 后采用"槽位随机化"：同一剧本每次运行金额/称谓/案情细节不同，解决重复感；
2. **圆谎机制**：用户指出破绽时允许 Agent 圆谎一次（真实骗子行为），第二次被戳穿则"骗子放弃退场"——既真实又给用户正反馈；
3. 阶段化目标驱动：每阶段设定"骗子目标"（建立信任→制造紧迫→收割），评估 Agent 同时追踪用户在哪个阶段失守，用于错题归因；
4. 护栏三件套：输出过滤（正则禁真实账号/链接格式）+ 水印 + 不可导出。

### 3.2 评估 Agent —— 中（必须规则兜底）

**改进建议**：
1. 规则特征引擎打底（关键词表/用时/行为布尔量）+ LLM 仅做自然语言解释，输出固定 JSON；
2. 增加"官方渠道核实"与"二次诈骗识别"两个指标（见 2.1-②）；
3. 建 30–50 条标注对话做回归测试集，每次调提示词后跑一遍，防止分数漂移；
4. 报告按"场景 × 失守阶段"二维归因（如"刷单返利 × 解冻金环节"），比单维分数更有训练指导价值。

### 3.3 自救 Agent —— 高

**改进建议**：
1. 分级处置从"风险等级 1–5 级"升级为**三维路由：风险等级 × 资金状态（未转/已转/已转超24h）× 场景类型**，方案更精准；
2. "黄金 30 分钟"话术永远置顶（止付成功率随时间骤降）；
3. **二次诈骗红色警报**：用户描述中出现"黑客追款/维权交费"字样立即强提醒；
4. 法条必须带原文引用，检索不到不引用（防幻觉）；六步方案均标注法律依据（本项目已实现：《反电诈法》第 20 条、《刑法》第 266 条、《民法典》第 148 条等）。

## 六、优先级与 MVP 建议

**优先级：欺诈 Agent ＞ 评估 Agent ＞ 自救 Agent。**

理由：①欺诈 Agent 承载核心体验与差异点（对比国家反诈中心 APP 的静态案例库，"交互式被骗"是唯一差异化）；②评估 Agent 可先用纯规则版上线（不需要 LLM 也能出分数），成本极低；③自救 Agent 本质是静态知识库+流程清单，最后做不影响闭环。

**MVP（建议 4 周内，1–3 人）**：
- ✅ 1 个场景端到端闭环（选**刷单返利**——公安部通报发案率第一）
- ✅ 剧本化欺诈对话（无 LLM 可运行）+ 规则版实时评估
- ✅ 错题本（本地存储，结构按您的设计）
- ✅ 分阶段自救清单（黄金 30 分钟置顶）
- ✅ 合规三件套：模拟训练水印 + 知情同意 + 不可导出

**砍掉**：LLM 自由生成话术、多人群聊找骗子、语音/AI 换脸模态、排行榜、账号体系、8 场景全做（先 1 个场景打磨透）。

**第二期**：LLM 话术润色与追问适配、评估报告 LLM 化归因、错题本驱动场景推荐、扩至 3–4 个场景。

## 七、对提示词本身的改进建议

1. **明确技术形态**：「Trae 生成 Agent」请写清——调用哪个模型 API？有无后端？预算多少？否则技术评估只能给区间判断；
2. **写明目标用户与使用场景**：学校宣教、个人自用、单位培训的产品结论完全不同（尤其商业维度）；
3. **量化验收标准**：目前指标全是定性描述，建议直接写入目标值（如"识别准确率 ≥ 80%"）；
4. **说明合规资源**：是否有法律顾问/法学院资源可审核话术与法条？这直接决定法律维度评级；
5. **补充竞品分析**：国家反诈中心 APP 已有案例库、风险查询、来电预警，需明确差异化定位（互动式训练是您的核心差异，应围绕它写）；
6. **指明输出用途**：课程答辩 / 立项评审 / 商业计划书的详略与口径不同；
7. **修改数据互通表述**：「全程记住用户全部对话」建议改为「保留结构化摘要 + 关键行为特征」——既省上下文成本，又满足《个保法》数据最小化原则；
8. **补充范围边界**：语音克隆/AI 换脸模拟是否在范围内？离线可用是否为硬性要求？未说明则按"否"评估。
